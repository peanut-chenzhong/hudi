# 分区级并发控制完整示例

## 场景说明

假设我们有一个 Hudi 表，需要同时使用 Flink 和 Spark 写入数据：
- **Flink 作业**：写入分区 `partition_2024_01`、`partition_2024_02`
- **Spark 作业**：写入分区 `partition_2024_03`、`partition_2024_04`

使用分区级并发控制，这两个作业可以完全并发执行，不会产生冲突。

## 完整配置示例

### 1. Flink 配置

```java
import org.apache.flink.table.api.EnvironmentSettings;
import org.apache.flink.table.api.TableEnvironment;
import org.apache.hudi.configuration.FlinkOptions;
import org.apache.hudi.common.model.WriteConcurrencyMode;
import org.apache.hudi.config.HoodieLockConfig;

public class FlinkPartitionBasedWrite {
    public static void main(String[] args) {
        EnvironmentSettings settings = EnvironmentSettings.newInstance().build();
        TableEnvironment tEnv = TableEnvironment.create(settings);
        
        // 创建 Hudi 表
        tEnv.executeSql(
            "CREATE TABLE hudi_table (\n" +
            "  id BIGINT,\n" +
            "  name STRING,\n" +
            "  ts BIGINT,\n" +
            "  partition_date STRING,\n" +
            "  PRIMARY KEY (id) NOT ENFORCED\n" +
            ") PARTITIONED BY (partition_date)\n" +
            "WITH (\n" +
            "  'connector' = 'hudi',\n" +
            "  'path' = '/path/to/hudi/table',\n" +
            "  'table.type' = 'COPY_ON_WRITE',\n" +
            "  'write.operation' = 'upsert',\n" +
            "  'write.concurrency.mode' = 'optimistic_concurrency_control',\n" +
            "  'write.lock.provider' = 'org.apache.hudi.client.transaction.lock.ZookeeperBasedLockProvider',\n" +
            "  'write.lock.conflict.resolution.strategy' = 'org.apache.hudi.client.transaction.PartitionBasedConcurrentWritesConflictResolutionStrategy',\n" +
            "  'write.concurrency.early.conflict.detection.enable' = 'true',\n" +
            "  'write.concurrency.early.conflict.detection.strategy' = 'org.apache.hudi.table.marker.PartitionBasedDirectMarkerDetectionStrategy',\n" +
            "  'write.recordkey.field' = 'id',\n" +
            "  'write.partitionpath.field' = 'partition_date'\n" +
            ")"
        );
        
        // 只写入 partition_2024_01 和 partition_2024_02
        tEnv.executeSql(
            "INSERT INTO hudi_table VALUES " +
            "(1, 'name1', 1640995200000, 'partition_2024_01'), " +
            "(2, 'name2', 1640995200000, 'partition_2024_01'), " +
            "(3, 'name3', 1641081600000, 'partition_2024_02'), " +
            "(4, 'name4', 1641081600000, 'partition_2024_02')"
        );
    }
}
```

### 2. Spark 配置

```scala
import org.apache.spark.sql.SparkSession
import org.apache.hudi.DataSourceWriteOptions
import org.apache.hudi.config.HoodieWriteConfig
import org.apache.hudi.config.HoodieLockConfig

object SparkPartitionBasedWrite {
  def main(args: Array[String]): Unit = {
    val spark = SparkSession.builder()
      .appName("Hudi Partition-Based Concurrent Write")
      .config("spark.serializer", "org.apache.spark.serializer.KryoSerializer")
      .getOrCreate()

    // 准备数据（只写入 partition_2024_03 和 partition_2024_04）
    val data = spark.createDataFrame(Seq(
      (5, "name5", 1641168000000L, "partition_2024_03"),
      (6, "name6", 1641168000000L, "partition_2024_03"),
      (7, "name7", 1641254400000L, "partition_2024_04"),
      (8, "name8", 1641254400000L, "partition_2024_04")
    )).toDF("id", "name", "ts", "partition_date")

    // 配置分区级并发控制
    val hudiOptions = Map(
      "hoodie.write.concurrency.mode" -> "optimistic_concurrency_control",
      "hoodie.write.lock.provider" -> "org.apache.hudi.client.transaction.lock.ZookeeperBasedLockProvider",
      "hoodie.write.lock.conflict.resolution.strategy" -> 
        "org.apache.hudi.client.transaction.PartitionBasedConcurrentWritesConflictResolutionStrategy",
      "hoodie.write.concurrency.early.conflict.detection.enable" -> "true",
      "hoodie.write.concurrency.early.conflict.detection.strategy" -> 
        "org.apache.hudi.table.marker.PartitionBasedDirectMarkerDetectionStrategy",
      "hoodie.datasource.write.table.type" -> "COPY_ON_WRITE",
      "hoodie.datasource.write.operation" -> "upsert",
      "hoodie.datasource.write.recordkey.field" -> "id",
      "hoodie.datasource.write.partitionpath.field" -> "partition_date",
      "hoodie.datasource.write.table.name" -> "test_table",
      "hoodie.datasource.write.path" -> "/path/to/hudi/table"
    )

    // 写入数据
    data.write
      .format("hudi")
      .options(hudiOptions)
      .mode("append")
      .save("/path/to/hudi/table")
  }
}
```

## 验证并发写入

### 1. 同时启动两个作业

```bash
# 终端1：启动 Flink 作业
flink run -c FlinkPartitionBasedWrite flink-job.jar

# 终端2：启动 Spark 作业
spark-submit --class SparkPartitionBasedWrite spark-job.jar
```

## 性能对比

### 文件组级 vs 分区级并发控制

| 场景 | 文件组级 | 分区级 |
|------|---------|--------|
| 不同分区写入 | 可能冲突（如果文件ID相同） | ✅ 无冲突 |
| 相同分区写入 | 冲突 | 冲突 |
| 冲突检测开销 | 较高（检查文件ID） | 较低（只检查分区） |
| 适用场景 | 细粒度控制 | 分区隔离场景 |

## 注意事项

1. **分区分配策略**：确保不同写入者写入不同的分区
2. **锁提供者**：必须配置 Zookeeper 或其他锁提供者
3. **早期冲突检测**：推荐启用，提前发现冲突
4. **监控**：监控冲突率，评估分区分配策略的有效性

## 故障排查

### 问题：仍然检测到冲突

**检查清单**：
1. ✅ 确认配置项正确设置
2. ✅ 验证两个作业写入的分区是否真的不同
3. ✅ 检查日志中的分区路径
4. ✅ 确认使用的冲突解决策略类名正确

### 问题：早期冲突检测未生效

**检查清单**：
1. ✅ 确认 `hoodie.write.concurrency.early.conflict.detection.enable` 设置为 `true`
2. ✅ 验证 Marker 类型为 `DIRECT`
3. ✅ 检查早期冲突检测策略类名正确
4. ✅ 查看日志中的早期冲突检测信息
